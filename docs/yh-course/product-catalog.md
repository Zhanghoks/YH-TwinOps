# 商品目录与本地存储

本目录服务于原创商品模型和密集版试换陈列，不是采购、库存或真实门店商品系统。

## 三层边界

1. 商品定义：随仓库版本化的16条示意商品seed，稳定SKU/商品ID、中文名称、类别、规格、参考尺寸和温区。
2. 模型注册：模型key指向现有独立`DetailedProductKind`几何，不把商品名称当模型标识；改显示名称不改几何或业务ID。
3. 陈列映射：从密集版五个试换点的实际挂点确定性生成fixture/slot→SKU。共596个既有陈列对象，不代表新增库存，也不是声称默认开关已启用。每类模型是否上架由映射计数得出，肉盘等未使用模型仍可在目录查看。

## 持久化边界

目录seed可随仓库重建。本地可编辑字段仅是显示元数据，稳定SKU、模型key、尺寸与映射不能通过目录编辑器任意修改。浏览器localStorage保存同一浏览器/来源中的覆盖值；刷新保留，不支持多人共享、跨设备同步或服务端备份。浏览器清理数据、隐私模式限制或更换来源会影响本地覆盖。恢复原版只还原目录元数据，不触及门店业务和布局。

导出的JSON是目录与陈列映射快照，不是真实库存清单。编辑后的中文名称不会悄悄改变3D模型种类、商品数量或模拟经营信号。坏存储/版本不符要安全回退并显示状态；写入失败不假报保存成功。

## 当前实现

工作台顶部增加「商品目录」，保留3D、经营看板和Agent原状态。可搜索中文名称/SKU/模型键、按六类过滤，查看温区、参考尺寸（宽×高×深）、适用分区和候选关联数。名称、规格、备注可编辑；保存前检测非法输入，写入成功才更新已保存列表。恢复操作带二次确认。

种子使用显式固定 `PRODUCT_SKU_BY_MODEL`，数组重排不改变SKU身份。`placementProductKind.ts` 同时供渲染与映射使用，避免目录另抄规则漂移。当前13种关联596位：F029 144、F050 30、F074 30、F077 160、F107 232。罐头、带盖瓶和肉盘3种尚未关联本批试换位置。没有扩展到全店库存管理。

附件静态HTML包含搜索、分类、模型缩略图和可展开挂点，数据由同一导出函数生成，不同步项目中的localStorage编辑，不提供假后台。完整JSON含16条商品与596条映射，可用于检查或后续接入；项目内「导出JSON」导出当前浏览器编辑后的16条目录资料。
