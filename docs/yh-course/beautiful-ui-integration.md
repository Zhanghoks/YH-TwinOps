# YH 工作台：Beautiful UI 集成

本次重构的范围是 `apps/web` 的 YH-TwinOps 工作台。保留原来的 Three.js/R3F 场景、事件信号、运营模拟、商品尺寸和陈列结果。上游 Storewright 的独立应用不在本次改动范围内。

## 实际组件与适配方式

- [Beautiful UI](https://github.com/slev12397/beautiful-ui/tree/44a274e598395ab61e7c96c26fda2758780253b7) 的 PromptBar、ThinkingState、ContextCards 只呈现真实请求生命周期、真实返回的工具调用及其证据。不播放上游演示，也不把工具轨迹当作模型的内部思维。
- 按钮与视觉基础沿用上游 MIT 布局和语义 token，转译为普通 CSS，供顶栏、视角控件、经营看板和商品目录复用。ui-sdk 仍负责已有的可访问交互，包括分段控件、分栏、标签和折叠。
- 告警、方案与审批按统一的卡片、状态标签和按钮呈现。保持明确人工审批及回滚入口；不能触发真实门店操作。
- 3D 孪生、经营看板、商品目录是同级视图；只有经营看板显示指标与时段控件。三者共用同一当前情景，不因导航重建场景或聊天。
- 天气、车流、顾客和局部试换集中在「场景设置」。设置允许键盘打开和 Esc 关闭；目录中的 F077 铺满流程仍回到同一个画布视角。镜头切换通过同一个画布内的相机控制器完成；显示分区只切换标注可见性，避免同时销毁 R3F 场景与 HTML 标注。
- 没有引入 Next.js、收费图标、额外 npm 依赖、分析事件或演示附件上传流程。MIT 许可和改动说明见 `apps/web/src/ui/beautiful/` 与 `apps/web/src/ui/beautiful-agent/`，项目原有 AGPL 许可不变。

## 复验

```sh
npm run check
npm run build -w @yh/web
npm run dev -w @yh/web
```

无服务端时前端可以用浏览器本地规则工作，截图须标明离线分支。要验证在线接口，在单独终端执行 `npm run start -w @yh/api`，以 Vite 代理的实际请求核实工作台显示的是服务端规则或已明确配置的模型。不要用离线截图声称已测试服务端接口。

浏览器建议检查：正常进入 3D 场景、发送预设或手动问题、展开工具/证据、三个兄弟页签切换、查看经营看板和商品目录、F077 全架铺满及撤回、窄屏滚动和键盘聚焦。场景商品仅为合成陈列，不代表实际库存。
