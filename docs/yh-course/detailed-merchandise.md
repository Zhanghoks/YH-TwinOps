# 试换点位的独立商品模型

本轮商品模型属于原创、确定性的视觉陈列资产，不是实际品牌、扫描SKU或库存主数据。只接入已批准的本地密集版试换点位，不变更默认旧版开关、原业务ID、运营数据或设施布局；其余店内商品不被自动替换。

## 分离与回退

`detailedProduct.ts`描述独立商品部件，`detailedProductThree.ts`由同一描述生成真实几何。商品模型的输入尺寸为原挂点已核验的包络上限，局部原点位于底面，x/z居中。展示模型由 `shelfGroupReplacementThree`、`freshGroupReplacementThree`、`serviceGroupReplacementThree` 按原商品身份和挂点放置。设施结构和商品保持分离；空架仍没有商品。Three工厂的 `products: 'legacy'` 可用于同设施旧示意商品对照，默认 `detailed` 仅影响已启用的试换设施。

细化通过软袋封口、瓶盖和泵嘴、洗衣液开口把手、纸巾抽取口、果梗和叶片、奶盒斜顶和杯口等真实几何表达。无外部照片、品牌复制、AI效果图或新增贴图依赖。近远档保留商品身份和数量，远档减少微小部件；材料批处理避免每件商品单独绘制。

## 量测边界

商品只在现有已缩放包络内重构，不把原代理尺寸宣称为实物SKU尺寸。原为球体的果蔬允许改变剪影，但仍约束在旧局部尺寸盒内，而不是声称处处位于旧球面之内。姿态与倾角沿用挂点坐标。商品分组数不等于经营销量、库存或顾客计数。

预览使用同源实际几何，前后设施相同，仅商品表现改变。离线渲染不等于实时WebGL验收，不加载网页程序纹理、人物、天气及运营覆盖层。

## 实际接入范围

共5处、596件原有商品：F077 160件（53软袋、39罐、68纸盒）；F107 232件（77泵瓶、97带孔把手洗衣液、58纸巾包）；F029 144件（苹果、柑橘、绿叶菜按陈列格分组）；F050 30件（冷冻软袋与冻盒）；F074 30件（奶盒与酸奶杯）。只改变显示种类与形状，原商品对象身份与原始数据保留。独立商品库含16种，未使用的瓶装、罐装或肉盘不冒充已摆入店内；F007肉柜、F120收银、F032精选货架此次仍保留上一版商品。

## 性能与访问限制

近/远档采用不同曲面段数和细节，批处理后F077/F107各6个mesh；F029近6/远5；F050/F074各7。增加细节仍增加三角形，例如F107远档从约6604到24544，合批不等于GPU成本不变。本轮未得出浏览器FPS提升或实时性能验收结论。

本轮再试当前工作树127.0.0.1:5176服务，云浏览器报告ERR_CONNECTION_REFUSED，观察错误页又遭URL策略限制。没有修改浏览器安全设置或接受新条款，转为同源几何离线检查。

日配奶盒与酸奶杯进一步采用类型比例等比放入上限，奶盒W:H:D=.34:1:.34、酸奶杯1:.9:1，避免旧宽扁代理包装把奶盒拉成横卧屋脊；保留原底面与XZ挂点。陈列可能比原色块稀疏，不用虚增商品数量填满空隙。

新增19项独立商品模型检查、4项货架集成检查和40项商品安全检查。包括实际顶点包络、瓶标签边缘、真实手柄孔、果蔬倾斜挂点、商品之间和结构之间的净空、近远档、空架及旧模型回退。旧fresh/service测试中单Mesh假设改为明确旧商品路径，新细模由实际顶点检查覆盖。

最终项目验证：全量类型检查通过，根85个测试文件738项通过；Web首次并行负载中综合控件测试超默认5秒，未改测试超时或断言，原样复跑7文件14项通过。生产构建通过（最终重建8.81秒，既有chunk体积警告保留）。原dirty工作区状态逐字比对未变；未提交、推送、部署。

最后目检同时修正果蔬的旧扁球拉伸：苹果/柑橘按1:.95:1、叶菜1:.85:1等比contain-fit。宁可在原陈列格中较小，也不把苹果压成饼状或任意扩大高度引发碰撞。
