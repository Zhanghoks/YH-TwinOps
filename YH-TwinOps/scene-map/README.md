# YH TwinOps 试点门店基线场景（Blender）

依据 `~/Downloads/SPEC.md`（YH TwinOps §4.1 / FR-01 / §6.2 约束参数）设计的模拟永辉生鲜区三维场景地图。
**合成数据 · 非永辉官方运营系统**——场景内悬挂标识与场景自定义属性 `synthetic_data=True` 均已标注。

## 文件

| 文件 | 说明 |
|---|---|
| `create_scene.py` | 参数化生成脚本（唯一事实来源，可复现；调整参数后重跑即得新版本） |
| `yh-fresh-area.blend` | 主 Blender 项目（保留最新窗口打开） |
| `preview-top.png` | 俯视平面图 1920×1440（无阴影，图纸风格） |
| `preview-iso.png` | 轴测三维视图 1920×1080 |
| `render-done.txt` | 每轮脚本完成的标记文件 |

重新生成：`/Applications/Blender.app/Contents/MacOS/Blender --python create_scene.py`

## 场地参数（与 SPEC 教学数据一致）

- 生鲜区净尺寸：**24 m（东西）× 18 m（南北）**，外墙高 3.0 m
- 货架通道（Run）：**12 条，R01–R12**，单条深 1.1 m、长 10 m（南北向），按 6 组背靠背货架岛排布
- 商品品类：**4 类**，每类 3 条通道（`category_id` 与后续 StoreConfig / 模拟 POS CSV 映射对齐）

| category_id | 名称 | 颜色 | 通道 |
|---|---|---|---|
| `cat_veg` | 蔬菜 | 绿 | R01–R03 |
| `cat_fruit` | 水果 | 橙 | R04–R06 |
| `cat_meat` | 肉品 | 红 | R07–R09 |
| `cat_seafood` | 水产 | 蓝 | R10–R12 |

## 布局与业务约束可视化

- **顾客入口**：南侧 x 10.0–13.0（宽 3.0 m），中轴 **x=11.5 与 2.4 m 中央主通道中轴重合**（`preserveEntrances` 约束的演示要素）
- **次通道**：4 条，各 **1.4 m ≥ minPassageWidthM(1.2)**，地面文字直接标注宽度；西侧沿墙 0.9 m 与服务台前 1.1 m 为**员工作业通道**，不计入 minPassageWidthM（该参数约束 4 条顾客次通道）
- **结构柱**：4 根（C1–C4，0.5×0.5 m）嵌于主通道南北两段的柱位行（y≈5.5 / 13.5），柱间最窄 **1.34 m** ≥ minPassageWidthM(1.2)——调改中不可移动的固定约束；脚本在渲染前内置 bbox 断言，保证柱与货架/设施/标牌零相交
- **北侧**：蔬菜风幕柜（x 1.0–5.6）、果切冷链柜（5.9–10.9）、肉品加工台（12.7–17.4）、水产冰台（17.7–20.8）——设备 x 区间对齐品类 run 跨度、只面对本品类通道；后仓门（21.0–22.8 m）前不布设备，R12 靠北端吊牌识别；后仓门旁周转筐区
- **南侧**：4 个促销堆头（箱口堆货 + POP 特价牌）、自助称重台×2（主通道口两缘）、品类图例与 2 m 比例尺；入口旁购物篮堆；**东侧**：服务台、"→ 至收银区"动线提示
- **数字孪生属性**：每条通道的所有网格对象都带有自定义属性 `run_id / category_id / category_name`（对应 FR-01"选中货架查看 id、品类"）；场景级属性 `store_id="YH-SIM-001"`、`synthetic_data=True`；每条通道南北两端均挂吊牌、层板顶面有顶视编号、柜顶有平贴字，俯视/轴测均可读

## 与后续开发的衔接

- 布局坐标可直接转写为 Storewright `StoreConfig.layout.runs[]`（通道矩形 x0/y0/x1/y1 + categoryIds）
- 候选方案（MOVE_RUN / REASSIGN_CATEGORY patch）可在同一脚本参数上做差分，保证 3D 预览与仿真输入一致
- 蔬菜区贴西侧与入口（风幕柜 1.0–5.6 正对 R01–R03）、肉品/水产加工台正对本品类通道（12.7–20.8 覆盖 R07–R11）——为 Agent 启发式①"高频品类靠近入口"预留了可解释的基线故事
